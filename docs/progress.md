## Phase 3 — 능동성 (진행 중)

**설정 영속 + 두뇌 런타임 교체 — GUI 설정 팝업 (2026.09.01, PR 3분할):**

- **한 줄:** GUI에서 두뇌 벤더를 고르고 API 키를 넣으면 **재기동 없이 두뇌가 바뀌고, 그 선택이
  재기동 후에도 남는다.** 부수 효과로 **gui.md:121의 구멍(런타임 변경이 재기동 시 config로 복귀)이
  닫혔다** — A2에서 취침창으로 실증됐던 그 부채다.
- **출발점은 "키를 SQLite로 옮길까?"였고, 평가 결과 셋으로 갈렸다.**
  - **① 키는 `.env`에 남긴다.** 키는 벤더사에 원문으로 보내야 해서 해싱이 불가능하고,
    `navi.db`는 백업·이관·디버깅 때 **통째로 복사하는 기억 파일**이라 *"기억 파일 하나 보내줘"* 가
    곧 키 유출이 된다. 지금의 분리가 이미 맞았다. (keyring/DPAPI는 의존성·헤드리스 경로
    부담으로 보류 — 사용자 확인 2026.08.31.)
  - **② 비밀 아닌 설정은 영속돼야 한다.** 사용자가 고른 값과 개발자가 적어 둔 기본값이 같은
    자리를 다투면 안 된다. 자리는 `navi.db`의 `setting` 테이블.
  - **③ 진짜 작업은 저장소가 아니라 재구성 경로였다.** `Config`는 frozen이고 `load_config`는
    부팅 1회만 돈다 — 키는 그 시점에 `create_brain`을 거쳐 벤더 클라이언트로 굳고 pipeline이
    그 인스턴스를 붙든다. **값만 바꿔선 아무 일도 안 일어난다.** 테이블만 만들었으면 절반도
    못 푼 셈이다.

- **설정 층위가 3층 → 4층.** `config.yaml < config.local.yaml < DB(사용자 오버라이드) < CLI`.
  CLI가 여전히 최상위인 건 *"이번 실행만"* 이 저장된 선택보다 좁고 명시적이라서다.
  - **화이트리스트 필수**(`_SETTING_KEYS`, 지금은 `brain.vendor` 하나). 아무 키나 DB에서 덮게
    하면 `db.path`를 DB에서 읽는 **부트스트랩 순환**이 생긴다.
  - **2단계 로드** — DB를 열려면 `db_path`가 필요한데 그건 yaml(+CLI)이 정한다.
    ① yaml·local·CLI로 `db_path` 확정 → ② 그 DB에서 오버라이드 → ③ 나머지 CLI.
  - **`_read_settings`는 `MemoryStore`를 쓰지 않는다.** 그쪽 `__init__`이 `executescript`로
    DB 파일과 스키마를 만들어서, preflight·GUI 런처가 `load_config`만 불러도 **빈 navi.db가
    생긴다.** 설정을 읽는 행위가 파일을 만들면 안 된다.
  - **CLI `--brain`/`--db`를 `load_config` 안으로 옮겼다.** 밖에서 `replace`하면 DB 층이
    `--db`가 아닌 yaml의 `db_path`를 읽고, 저장된 설정이 CLI를 이기는 역전도 생긴다.
    **층위 순서가 한 곳에만 존재하게 됐다.**
  - `setting`을 `key/value` 일반형으로 둔 건 **마이그레이션 경로 부재**(`executescript` +
    `IF NOT EXISTS`) 때문 — 손잡이가 늘어도 컬럼을 못 늘리는 상황이 안 온다.

- **교체 순서가 계약이다 — 검증에 성공한 뒤에야 무엇이든 커밋한다.** 계획서엔 *"키가 오면
  먼저 `.env` 갱신 → Config 재생성"* 으로 적혀 있었는데, 그러면 검증 실패 시 **멀쩡하던 키가
  이미 덮인 뒤**라 같은 문서의 "부분 적용 금지"와 충돌한다. 순서를 뒤집었다: 후보 키는
  `.env`·환경을 거치지 않고 **후보 Config에만** 넣어 검증하고, 통과해야
  `.env`·`os.environ`·pipeline·`setting`을 한꺼번에 갱신한다.
  - `BrainAdapter.validate`가 최소 요청 1회로 **"말을 시켜야 터지는" 실패를 교체 시점으로
    당긴다.** 실패는 `BrainAuthError`(키) / `BrainUnavailable`(네트워크) 둘로만 올리고, 벤더
    예외를 이 둘로 옮기는 건 각 어댑터의 몫이다(벤더 종속은 어댑터 뒤에 — 설계 원칙 1).
  - 패턴은 `SwapRuntime.swap_persona`를 그대로 따랐다(값 교체 + 협력자 재생성 +
    `_guard_not_playing` + 실패 시 미적용). 새 메커니즘을 만들지 않았다.
  - **요약기는 건드리지 않는다** — `_build_feed`가 별도 인스턴스를 만든다. 어댑터 하나는
    동시 요청 1건이 계약이라 공유하면 선제 발화와 수집이 `last_result`를 두고 경합한다.
  - `navi.brain`이 `BRAIN_VENDORS`·`BRAIN_KEY_FIELDS`·`BRAIN_ENV_NAMES`의 **단일 소유자**가
    됐다(preflight의 중복 정의 제거) — 부팅 전 점검과 런타임 교체가 같은 재료를 봐야
    "키 있음으로 보이는데 막히는" 어긋남이 안 생긴다. `availability`가 조회·실행에 같은
    함수를 쓰는 것과 같은 규칙.

- **비밀이 새는 자리를 네 군데 막았다.** `Config`의 키 필드 `repr=False`(frozen dataclass 기본
  repr는 원문을 찍고, 예외 트레이스백의 지역변수 덤프가 그걸 탄다) · 응답은 마스킹
  (`sk-ant****nQAA`, 앞 6자는 발급처 접두사라 비밀이 아니다) · `.env`는 줄 단위 부분 갱신 +
  `os.replace` 원자 교체 · **`POST /brain`의 `api_key`는 `pydantic.SecretStr`** — 평범한 `str`이면
  본문 검증 실패 시 **FastAPI가 입력값을 그대로 422 응답과 예외 로그에 싣는다.**

- **GUI는 설정 팝업으로.** 두뇌를 페르소나 패널에 끼워 넣지 않고 헤더에 톱니를 두고 팝업을

**D9 폐기 — 친밀도 시스템을 v1 설계에서 제외 (2026.08.31):**

- **한 줄:** 친밀도 점수 누적 → 단계별 페르소나 프로필 전환을 **폐기**했다. Phase 4는
  이제 **기억 하나의 축**이다(장기기억·사실 충돌·망각).
- **이 결정은 원래 더 전에 내려졌는데 기록되지 않아 유실됐다.** 사용자가 로드맵 브리핑을
  듣다가 *"이거 폐기하자고 얘기했던 적 있었던것같은데"* 라고 짚어 복원했다. 리포 전수 검색
  (문서·커밋 본문·메모리)에서 **폐기 흔적이 하나도 안 나왔다** — 반면 다른 폐기들(두뇌 워밍업,
  Vosk, Gemini Live, "한국어 퍼스트", 가중치+jitter 산식)은 전부 남아 있었다. 전역 지침
  *"결정은 repo에 남긴다 — 채팅에만 있는 결정은 다음 세션에 사라진다"* 의 **실증 사례**다.
- **폐기 이유 ① 캐릭터 카드 설계가 예측 불가해진다.** 단계별 프로필은 `example_dialogues`를
  단계 수만큼 쓰게 만든다. 그런데 few-shot 대화쌍은 말투 형성의 **핵심 재료**다. 작성자가
  "이건 서먹한 단계, 이건 편해진 단계"를 상상하며 톤 차이를 일관되게 유지해야 하는데, 그 차이는
  **말로 정의되지 않고 예시로만 존재한다.** 카드가 막으려던 것(말투 흔들림)을 카드가 만든다.
- **폐기 이유 ② 오르내림 기준을 정할 수 없다.** `shared_vulnerability: true`가 몇 점인가?
  사흘 침묵은 몇 점을 깎나? 종이로 못 정한다. **로그로도 못 닫는다** — 페르소나가 이미 그 점수에
  따라 변해 있어 **측정과 개입이 얽힌다.** hazard 튜닝(B2)과 결정적으로 다른 점이다: hazard는
  발화 *여부*만 바꾸므로 로그가 판정해 주지만, 친밀도는 **관측 대상 자체를 바꾼다.**
- **잃은 것이 작다.** "톤이 변한다"는 체감은 **무드(D14 빠른 경로)가 이미 제공**하고 실기까지
  끝났다(PR #35·#39). 무드는 턴 단위 감정이라 관계 누적과 축이 다르지만 *체감되는 자리*는 같다.
  "같이 산 시간"은 점수가 아니라 **기억**으로 표현한다 — 한 달 전 얘기를 다시 꺼내는 쪽이
  점수 상승보다 직접적이다.

  프레임이 **금지**를 맡는다.
- **★ 리뷰에서 카드 종속이 잡혔다(같은 세션 내 자체 수정).** 1차 구현에서 프레임에

  못 나간다"* 처럼 **스스로를 제약하는 카드는 경로도 스스로 줘야 한다**는 원칙이 생겼다.

| **급히 덧댄 정리 코드** | ③정규식이 정상 문장 훼손 ④엔티티 미해제 ⑥이중 unescape | 실측 반응으로 같은 세션에 추가 — 방어가 과하거나 불완전 |
| 관용구 | ⑦`k or 기본값`이 0을 삼킴 | falsy 함정 |

- **①이 가장 컸다.** 한 배치는 `fetched_at`이 전부 같아 tiebreak가 삽입 순서를 뒤집는데, RSS는
  최신이 앞이라 **가장 낡은 기사가 `[0]`에 왔다.** `pick_topic`은 `[0]`만 쓴다. `published_at`
  컬럼을 추가해 `COALESCE(published_at, fetched_at) DESC`로 고쳤는데, **이 리포엔 마이그레이션
  경로가 없어**(`executescript`+`IF NOT EXISTS`가 전부) 운영 `navi.db`에 테이블이 생기기 전인
  그 시점이 **컬럼을 공짜로 추가할 마지막 창**이었다.
- **⑤는 첫 해법이 틀렸다.** "적재 0이면 실패"로 고치면 **조용한 피드를 매 tick 두들긴다** — 새
  기사가 없어 dedup으로 전부 걸리는 건 정상이다. 소스별로 셋(응답/시도/적재)을 따로 세서
  **"시도했는데 전멸"**을 가린다. 특히 **요약기 전멸**(쿼터 소진)은 소스가 멀쩡해 적재 건수만
  보면 조용한 피드와 똑같이 생겼다 — 안 가리면 키만 바꾸면 될 장애를 12시간 방치한다.
- **검증 방식:** 매 수정마다 **커밋 후 소스만 옛 동작으로 되돌려 새 테스트가 빨간지 확인**했다.
  이걸로 회귀 가치가 0인 테스트를 하나 잡았다(1회차엔 `last_collect_at`이 `None`이라 naive/aware가
  섞이지 않아 수정 전에도 통과).

**순서 4 후속 — 2층 타이밍을 tick 기반 hazard로 교체 (2026.07.18, `refactor/timing-hazard`, 체크리스트 B1):**
- **범위:** 배선 당시 예고한 "조건 산식 재구상". `should_initiate`를 고정 임계값+외부 jitter에서
  **변동확률(Weibull hazard)**로 교체. 계약(bool 반환)·게이트 순서·`daily_cap`·로깅은 무수정 —
  조건이 bool 뒤에 격리돼 있어 산식만 갈렸다(순서 4 설계 확인 항목대로).
- **교체 중 드러난 구 산식의 결함(우려가 아니라 실재):** 구 산식은 매 tick(10s) jitter를 새로
  뽑아 `elapsed >= base/w*jitter`를 봤다. elapsed가 jitter 하한에 닿는 순간부터 10초마다 주사위를
  다시 굴리니 **반복 샘플링이 산포를 하한으로 무너뜨린다.** 2000회 시뮬레이션 실측: 의도한
  48~72분(±20%) 대신 평균 50.4분·산포 3.8분(5~95%)에 눌어붙고, tick을 1s로 줄이면 48.8분·
  1.3분까지 더 붕괴 — **tick 빈도가 나비의 발화 성격을 바꾸고 있었다.** 지금까지 쌓였을 로그가
  이 왜곡된 조건의 기록이라 B2 튜닝의 오염원이 될 뻔했다.
- **새 산식 — Weibull 생존함수 S(t)=exp(-(t/λ)^k):** 매 tick 조건부 발화 확률
  `p = 1 - S(t+dt)/S(t)`를 굴린다. 매 tick 생존확률의 곱이 telescoping되어 전체 생존확률이
  정확히 S(t)로 떨어지므로 **tick 빈도 중립성이 근사가 아닌 항등**으로 따라온다(실측: tick 10s
  평균 62.3분 vs 1s 63.1분, 산포 75분 동일). λ=base_interval_s/시간대가중치(가중치 방향 보존),
  k=2 → 경과할수록 발화 확률↑("오래 안 봤을수록 말 걸 기운이 오른다"), k=1이면 무기억 지수분포.
- **정리된 것(순서 4가 예고한 3건):** ① jitter_range 폐지 — 무작위성이 산식에 내장돼 붕 뜬다,
  자리는 `hazard_shape_k` ② tick 빈도 정규화 — `tick_interval_s`를 산식에 넣어 위 telescoping으로
  해결 ③ 테스트 결정성 — seed 주입 대신 확률 계산(`initiation_probability`)을 난수 없는 순수
  함수로 분리(산식 전체가 결정론 검증, RNG는 경계 한 곳). test_daemon 결정론도 base/min=0
  상수화(hazard에선 척도가 무너져 불가)에서 rng 고정으로 이동.
- **값은 여전히 배선용 대충값** — 바뀐 건 산식의 꼴이지 튜닝이 아니다. 좋은 값은 interaction_log
  축적 뒤(B2, 진행 원칙 2). **검증:** 228 green(timing 8건 재작성 — tick 빈도 중립성·hazard
  단조성·k=1 무기억). arch 4.4·aliveness.md 2.1의 "가중치+jitter" 표현도 hazard로 최신화.

  user_overrode} — 능동성 튜닝의 원천 데이터.
- **DaemonCore tick 배선([navi/daemon.py](../navi/daemon.py)):** TICK마다 게이트를 순서대로 통과해야

  `pick_topic`(3층)으로 트리거를 만들어 conductor→brain→mouth로 흘리고 initiated 로그. 검문①(오버라이드)·
  검문②(취침창)는 손대지 않음 — 이번 발화는 그 게이트 통과 뒤에만 동작. 능동 발화는 사용자 발화가
  없으므로 기억엔 나비 답변만 `trigger_type=proactive`로 남긴다(가짜 user 턴 안 만듦).

- **설계 확인 — 조건은 bool 뒤에 격리:** `should_initiate`가 bool만 반환하고 게이트·대기·로깅은
  조건-불가지론이라, 나중에 변동확률(시간 경과에 따른 발화 확률↑, tick 기반 hazard) 등으로 산식을
  갈아끼워도 배선 재사용. 교체 시 정리할 것 = jitter 파라미터 위치(내부 RNG로 옮기면 붕 뜸)·tick 빈도

**Stage 1 — CosyVoice2 zero-shot 청취 (레퍼런스: 블루아카이브 아리스 일본어 보이스):**
- **CosyVoice2 기준 한국어 출력(cross-lingual) = 불가.** 일본어 레퍼런스→한국어 발화는 깨진 소리. → 이 모델에서는 동일 언어 출력만 유효.
- **언어 방향은 미확정.** 현재 테스트가 일본어 레퍼런스(아리스)를 쓰고 있어 일본어 출력을 먼저 검증한 것. 한국어 레퍼런스 음원 탐색 중이며 일/한 양방 지원도 검토 중. GPT-SoVITS가 교차언어를 더 잘 처리한다는 보고 있음 — fine-tune 비교 시 함께 확인 예정.
- **일본어 출력 = "아주 그럴듯함".** 존댓말 캐릭터 어투가 새 문장에서도 잘 유지됨. zero-shot치고 충분히 좋음.
- **한계 두 가지(실청취):**
  - **캐릭터성 평탄화** — 원본의 활기참·강아지 같은 인상이 다소 눌려 "차분한 아리스" 톤. (단 레퍼런스 톤을 따라가므로 차분한 Lobby 레퍼런스 탓일 여지 있음 — 활기찬 레퍼런스로 재시도 중.)
  - **음질 저하 + 간헐 노이즈** — 출력 24kHz 고정이라 스튜디오 원본(무손실)보다 선명도 손실(neural vocoder 구조적 천장, 모델 무관). 노이즈는 zero-shot hallucination·ref-text 정렬 실패(긴 레퍼런스일수록↑).
- **평가:** CosyVoice2는 일반 음성(뉴스·오디오북) 학습이라 서브컬처 캐릭터 억양을 평탄화하는 경향이 실제로 있음. 단 "캐릭터성 완전 소멸"은 과장 — 일본어·존댓말은 충분히 살아있음.

- **운영 함의:** 나비 데몬에서 무드별 레퍼런스 클립 풀을 두고 상황(차분한 밤 인사 / 신난 아침 등)에 맞춰 레퍼런스를 골라 끼우면 톤 제어 파이프라인 구성 가능.

  - **PowerShell 5.1은 BOM 없는 .ps1을 cp949로 읽어** 한글 주석에서 파싱이 깨진다. run_navi.ps1은

    pwsh(7.x)로 실행해 왔기에 드러나지 않았다(별도 수정 대상).
  - 종료는 `-Mode stop` / Ctrl+C / `POST /shutdown`.
